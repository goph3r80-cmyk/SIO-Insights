# Forum-submission output mode

Use when the user asks for a register item (or edition finding) to be
prepared for a capability-development forum. This produces a
**submission draft** in the house staff-paper shape — it is a drafting
aid, not a record of anything tabled.

## Structure

```
<reference block — leave as placeholder: file ref, date>

Chairman and Members of <FORUM>

<TITLE IN CAPS — subject, framed as the decision or observation>

AIM
1. To <seek approval for / apprise <forum> of / seek direction on> ...

OVERVIEW
2. <2-4 sentences: the question register context — which question, what
   changed, why it clears the material-change test and the COS-GS
   filter.>

<BODY SECTIONS — one heading per finding or option>
3-n. <Evidence with grading labels carried through ([Official],
   [Reported — single source], etc.); deltas stated against the Army
   baseline where one exists, or the missing baseline flagged as the
   precondition. Options in decision form: approve / trial / fund /
   reject, each with resource implication and pathway named per the
   AOTO discipline (instrument, funding basis, executing agency,
   schedule).>

CONCLUSION
n. Submitted for <FORUM>'s <approval / information / direction>, please.

<<Sent via email>>

<APPOINTMENT>
<e.g. CSIO / Hd R&T (Army)>

Prepared by   : <appointment only, e.g. TECHINT Officer, AS Br 2, SIO>
With inputs from : <appointments only>
Vetted by     : <appointment only, e.g. Hd AS Br 3, SIO>
Cleared by    : <appointment only, e.g. CSIO>

Annexes:
A. <evidence annex — the graded feed extract>
B. <as needed: EEI list, cost basis, comparator table>
```

## Rules

1. **Appointments only, never names.** The drafting chain (prepared /
   inputs / vetted / cleared) is expressed purely by appointment. If
   the user supplies names, replace them with appointments in any
   generated artifact.
2. **No fabricated formality.** Leave file references, dates, and copy
   numbers as placeholders for the user. Never invent classification
   markings — these drafts are built solely from the open-source
   register and carry none.
3. **Evidence grades survive the reformat.** A claim that was
   `[Reported — uncorroborated]` in the register stays labelled in the
   paper; syndication ≠ corroboration applies to staff papers exactly
   as to editions.
4. **One paper, one landing zone.** A submission targets one forum and
   one decision. If drafting surfaces a second decision, that is a
   second paper.
5. **Vet before it ships.** A submission draft derived from register
   content should pass through the sio-vetting-panel skill (two-pass
   review) before delivery; the vetting minute names this forum as the
   destination.
